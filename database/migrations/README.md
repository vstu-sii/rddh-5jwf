# Миграции схемы

Базовая версия схемы — [`../schema.sql`](../schema.sql) (миграция 0001). Она применяется:

- в dev — автоматически при первом старте `expense_db` на пустом volume (`/docker-entrypoint-initdb.d`);
- в CI — job `schema` накатывает её на чистый PostgreSQL 16 с `ON_ERROR_STOP=1`.

Пересоздать dev-базу с нуля: `docker compose -f compose.dev.yml down -v` (удалит данные), затем `up`.

## Правила с лабы 3

1. Схема меняется только новой миграцией, уже применённые файлы не редактируются.
2. Имя файла: `NNNN_<что_меняем>.sql`, например `0002_add_category_limits.sql`; внутри — `BEGIN; … COMMIT;`.
3. В том же PR правятся `schema.sql` (актуальный снимок) и `erd.puml`.
4. Деструктивные изменения (удаление колонки, смена типа денег) — только через отдельный ADR с ценой решения.
5. Инструмент миграций (Alembic или SQL-раннер) выбирается в лабе 3 вместе с ORM `expense_store`; до этого baseline — `schema.sql`.
