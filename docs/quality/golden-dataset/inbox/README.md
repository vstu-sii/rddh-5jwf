# Inbox: новые примеры до приёмки

Сюда кладутся записи, которые ещё не приняты в набор. Формат — тот же JSONL, что и в `v1.jsonl`, поля по схеме [`schemas/golden-example.json`](../../../schemas/golden-example.json).

## Как положить пример

1. Создать файл `inbox/<source>_<YYYYMMDD>.jsonl` (например `inbox/run_errors_20261101.jsonl`).
2. Прогнать валидатор:

   ```bash
   python scripts/quality/check_golden.py docs/quality/golden-dataset/inbox/*.jsonl
   ```

   Красный результат — пример не принят, причина видна в выводе. Нельзя «поправить» пример, ослабив проверку.
3. Проверить глазами: нет ли PII, заполнен ли `meta.uc_id`, обоснован ли `reference.notes` при `confidence < 0.9`.
4. После приёмки Quality переносит записи в `v1.jsonl` (или в `v2.jsonl`, если меняется состав) и обновляет [`CHANGELOG.md`](../CHANGELOG.md).

## Приоритет источников

1. **Реальная ошибка прогона** — система ошиблась, эталон исправлен руками. Закрывает известную дыру прицельно.
2. **Реальный обезличенный чек** от респондента — проверяет, что набор не оторван от жизни.
3. **Синтетика по шаблону** — для систематического покрытия (краевые случаи × оба входа).

Подробности процесса — в [`../README.md`](../README.md), раздел «Владелец и процесс пополнения».

## Важно

Файлы в этой папке **не входят** в `v1.jsonl` и не учитываются метриками, пока не приняты. Валидатор гоняет их отдельно, чтобы непринятый пример не испортил счёт покрытия UC.
