- Повторы для SC-15: 4 записи — gs-033, gs-034, gs-035, gs-045.

**Исправлено в процессе приёмки (до выпуска v1):**

1. **Разметка болей PRD.** Девять записей были помечены `pain_4_contested_category`, хотя в PRD боль 4 — «дедлайн подачи легко пропустить». Номер боли был приписан содержанию, к которому не относится. Введено отдельное поле `scenario_ref`; `pain_ref` ограничен пятью реальными болями PRD (`enum` в схеме). Валидатор теперь ловит такое расхождение (`Q-08`, `pains`).
2. **Ошибка в README набора.** Было указано 4 записи с инъекциями (`gs-020, gs-021, gs-040, gs-046`), но `gs-040` в наборе нет — пропуск в нумерации. Фактически инъекций 3. Исправлено.
3. **Ложные срабатывания PII-эвристики.** Шаблон ФИО склеивал конец одной строки чека с началом следующей («Спортзал Дельфин\nОплата») и давал 6 ложных находок; фискальный номер ФН (16 цифр) ловился как номер карты. Оба шаблона уточнены, проверка `Q-06` теперь даёт 0 ложных срабатываний.

**Известные пробелы:**

- Боли PRD **4 (дедлайн)** и **5 (видимость статуса)** набором не покрыты — 0 записей. Это UX-слой, его измеряют `SC-09` и `SC-21` из `success-criteria.md`.
- Все данные синтетические: набор проверяет логику конвейера, но не доказывает качество на реальных термочеках и PDF из банков. Первые реальные (обезличенные) чеки — задача лабы 3.
