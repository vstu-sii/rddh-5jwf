# План Golden Dataset

## Источник примеров

| Источник | Что даёт | Объём (план) | Статус |
|---|---|---|---|
| Проблемные интервью (Mom Test) с 3–5 бухгалтерами-аутсорсерами | Живые формулировки боли, реальные примеры чеков/выписок, категории, которые бухгалтеры используют на практике | 15–20 пар | Запланировано (Lab 1, шаг 3 VO) |
| Собранные чеки/выписки от согласных клиентов (анонимизировано) | Реальные OCR-сырые данные, варианты наименований продавцов в выписке, смешанные категории в одном чеке | 10–15 пар | Зависит от доступа к данным |
| Синтетические примеры на базе типов шаблонов (сетевые магазины, АЗС, агрегаторы) | Покрытие edge-кейсов: нечитаемые фото, технические названия в выписке, один продавец — разные категории | 10–15 пар | Можно сгенерировать сразу |
| Исторические данные разнесения (если бухгалтер предоставит выгрузку из Excel/1С) | Эталонные категории от конкретного бухгалтера, его личные правила | 5–10 пар | Опционально |

**Итого целевой объём:** 30–50 пар «вход → эталон» к концу Lab 2.

## Происхождение и версия данных

| Правило | Описание |
|---|---|
| **Что можно брать** | Анонимизированные чеки/выписки, предоставленные добровольно респондентами интервью; открытые датасеты чеков (если есть); синтетические данные на базе публичных шаблонов чеков РФ (ФФД 1.2) |
| **Чего нельзя касаться** | Реальные ИНН/КПП/названия компаний клиентов без явного согласия; полные номера карт/счётов; персональные данные покупателей в чеках; данные из 1С/бухгалтерских баз без NDA |
| **Версионирование** | Каждый набор примеров помечается: `source=<источник>`, `version=<дата сбора>`, `anonymized=true/false`. Хранится в `data/golden/<source>_v<YYYYMMDD>.jsonl` |
| **Лицензия** | Только данные, полученные с согласия респондентов или сгенерированные синтетически. Никаких скрейпов закрытых источников. |

## Формат записи

Каждая запись — одна строка JSONL:

```json
{
  "id": "gs-001",
  "source": "interview_bh_01",
  "version": "2025-09-15",
  "input": {
    "type": "receipt_photo",
    "ocr_text": "ИП Иванов И.И.\nИНН 7701234567\nКасса 001 Смена 123\nЧек № 456 от 15.09.2025 14:32\nМолоко 3.2% 95р\nХлеб ржаной 42р\nИТОГО: 137.00\nНДС 10%: 12.45\nОплата картой: 137.00",
    "merchant_raw": "ИП Иванов И.И.",
    "amount": 137.00,
    "date": "2025-09-15T14:32:00",
    "payment_method": "card"
  },
  "reference": {
    "category": "Продукты питания",
    "subcategory": "Молочные продукты и выпечка",
    "vat_rate": "10%",
    "confidence": 0.95,
    "notes": "Типовая розница, чёткий чек"
  },
  "meta": {
    "segment": "accountant_outsource",
    "client_id": "client_01",
    "pain_ref": "pain_3_one_seller_diff_categories"
  }
}
```

**Поля:**

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | string | да | Уникальный идентификатор: `gs-<NNN>` |
| `source` | string | да | Откуда: `interview_bh_01`, `synthetic_receipt_01`, `bank_stmt_01` и т.д. |
| `version` | string | да | Дата сбора/генерации в ISO |
| `input.type` | enum | да | `receipt_photo` \| `bank_statement_row` \| `mixed_batch` |
| `input.ocr_text` | string | для фото | Сырой текст OCR (с ошибками, если есть) |
| `input.merchant_raw` | string | да | Наименование продавца как пришло (из чека или выписки) |
| `input.amount` | number | да | Сумма операции |
| `input.date` | string | да | ISO 8601 |
| `input.payment_method` | enum | нет | `cash` \| `card` \| `sbp` \| `unknown` |
| `reference.category` | string | да | Целевая категория расхода (из глоссария) |
| `reference.subcategory` | string | нет | Уточнение категории |
| `reference.vat_rate` | string | нет | Ставка НДС если определена |
| `reference.confidence` | number | да | Уверенность эталона 0–1 (1 = бухгалтер уверен на 100%) |
| `reference.notes` | string | нет | Комментарий: почему эта категория, какие правила сработали |
| `meta.segment` | string | да | Всегда `accountant_outsource` |
| `meta.client_id` | string | да | Псевдоним клиента для группировки |
| `meta.pain_ref` | string | нет | Ссылка на боль из PRD, которую пример иллюстрирует |

## Владелец датасета

| Роль | Ответственность |
|---|---|
| **Quality Engineer** | Владелец: структура, формат, версиямирование, приёмка новых примеров, запуск evals |
| **Product / VO** | Источник живых примеров из интервью, валидация категорий с респондентами |
| **AI Engineer** | Генерация синтетических примеров для покрытия edge-кейсов, парсинг OCR/выписок |

**Процесс добавления примера:**
1. Новый пример кладётся в `data/golden/inbox/<source>_<date>.jsonl`
2. Quality проверяет формат, дубликаты, соответствие глоссарию категорий
3. Принятый пример мержится в основной файл `data/golden/v<YYYYMMDD>.jsonl`
4. Тег версии в git: `golden-dataset-v<YYYYMMDD>`

## Критерии приёмки примера в датасет

- [ ] Формат валиден по JSON-схеме (см. `schemas/golden-example.json`)
- [ ] `reference.category` существует в `docs/glossary.md`
- [ ] `reference.confidence` обоснована (если < 0.9 — есть `notes` почему)
- [ ] `meta.pain_ref` ссылается на существующую боль из PRD
- [ ] Нет PII: ИНН/КПП реальных компаний заменены на маски, номера карт — замаскированы
- [ ] Есть `source` и `version` для трассируемости
