# План Golden Dataset

> Сегмент: компании 50–500 сотрудников с политикой компенсации расходов (см. `docs/prd.md`)
> Роль-владелец: Quality & Safety. Цель — набор «вход → эталон» для проверки распознавания и категоризации, а не коллекция «красивых чеков».

## Источник примеров

| Источник | Что даёт | Объём (план) | Статус |
|---|---|---|---|
| Проблемные интервью (Mom Test) с 3–5 бухгалтерами и 3–5 сотрудниками | Живые формулировки боли, реальные примеры чеков на курсы и спорт, категории и формулировки, которые бухгалтеры используют на практике | 40–60 пар | Запланировано (Lab 1, шаг 3 VO) |
| Чеки и PDF-онлайн-чеки от согласных сотрудников (обезличено) | Реальные OCR-сырые данные, реальные PDF из приложений банков, варианты названий продавцов, смешанные позиции в одном чеке | 40–60 пар | Зависит от доступа к данным и согласия |
| Синтетические примеры на базе типов шаблонов (языковые школы, фитнес-сети, онлайн-курсы, конференции) | Покрытие edge-кейсов: нечитаемые фото, PDF-скан без текстового слоя, один продавец — разные категории | 60–90 пар | Можно сгенерировать сразу |
| Исторические данные компенсаций (если бухгалтер предоставит выгрузку из Excel/1С) | Эталонные вердикты «компенсируется / нет» от конкретной компании, её политика | 20–30 пар | Опционально: без них план выполняется на нижней границе |

**Итого целевой объём:** 160–240 расходов при полном доступе ко всем источникам (сумма нижних границ даёт 160, верхних — 240), 100–150 при работе без исторических данных, когда источник «Исторические данные компенсаций» недоступен.

**Разбивка по входу.** Нижние границы выбраны так, чтобы выполнялось CI-правило DoD (`dod-draft.md`, «Golden dataset покрывает оба входа»): ≥ 30% записей каждого типа при любом достигнутом объёме.

| Вход | Целевая доля | Объём при 100–150 | Объём при 160–240 |
|---|---|---|---|
| `receipt_photo` (фото чека) | ~50% | 50–75 | 80–120 |
| `receipt_pdf` (PDF онлайн-чека) | ~40% | 40–60 | 62–96 |
| `mixed_batch` (пачка из нескольких файлов) | ~10% | 10–15 | 18–24 |

Пропорция привязана к SC-02 (паритет качества между входами: подмножеств должно хватать, чтобы разница в 5 п.п. была измерима, а не выведена из шума). Доля PDF держится выше порога 30% намеренно: при объёме ближе к нижней границе 30% от 100 — это 30 записей, и на таком подмножестве разница в 5 п.п. ещё различима.

## Происхождение и версия данных

| Правило | Описание |
|---|---|
| **Что можно брать** | Обезличенные чеки и PDF-онлайн-чеки, предоставленные добровольно респондентами; синтетические данные на базе публичных шаблонов чеков РФ (ФФД 1.2); PDF-структуры, воспроизведённые по публично описанному формату онлайн-чеков банков |
| **Чего нельзя касаться** | Реальные ФИО сотрудников и их платёжные данные; полные номера карт и счетов; реальные ИНН/КПП компаний без явного согласия; адреса и телефоны; данные из 1С/бухгалтерских баз без NDA |
| **Обязательное обезличивание** | ФИО сотрудника → `emp_<NN>`; полный номер карты → маска `****1234`; ИНН компании → маска или замена на тестовый; адрес → город |
| **Версионирование** | Каждый набор помечается: `source=<источник>`, `version=<дата сбора>`, `anonymized=true/false`. Хранится в `data/golden/<source>_v<YYYYMMDD>.jsonl` |
| **Лицензия** | Только данные с согласия респондентов или сгенерированные синтетически. Никаких скрейпов закрытых источников. |
| **Отзыв согласия** | Сотрудник может отозвать согласие; запись удаляется из набора, а в `CHANGELOG` набора фиксируется факт удаления без содержания |

## Формат записи

Каждая запись — одна строка JSONL:

```json
{
  "id": "gs-001",
  "source": "interview_emp_01",
  "version": "2026-09-23",
  "input": {
    "type": "receipt_photo",
    "file_ref": "data/raw/emp_01/lang_school_2026_09_15.jpg",
    "ocr_text": "ООО Языковой центр Лингва\nИНН 7701234567\nКасса 001 Смена 123\nЧек № 456 от 15.09.2026 14:32\nКурс английского языка B1, 8 занятий 12000р\nИТОГО: 12000.00\nНДС 0%: 0.00\nОплата картой: 12000.00",
    "merchant_raw": "ООО Языковой центр Лингва",
    "amount": 12000.00,
    "date": "2026-09-15T14:32:00",
    "payment_method": "card"
  },
  "reference": {
    "merchant_canonical": "Языковой центр Лингва",
    "category": "Обучение",
    "subcategory": "Английский язык",
    "vat_rate": "0%",
    "reimbursable": true,
    "confidence": 0.95,
    "notes": "Курс английского языка, попадает под политику компенсации обучения"
  },
  "meta": {
    "segment": "employee_expense_reimbursement",
    "company_id": "company_01",
    "employee_id": "emp_01",
    "pain_ref": "pain_4_contested_category",
    "capture_condition": "clear"
  },
  "run": {
    "submitted_at": "2026-09-14T19:22:00+03:00",
    "in_registry_at": "2026-09-15T09:10:00+03:00",
    "flagged_at": "2026-09-14T19:22:40+03:00",
    "decided_at": "2026-09-15T11:05:00+03:00",
    "status_final": "компенсирован",
    "rejection_reason": null,
    "status_log": [
      { "at": "2026-09-14T19:22:00+03:00", "from": null, "to": "загружен", "actor": "emp_01" },
      { "at": "2026-09-15T09:10:00+03:00", "from": "загружен", "to": "в реестре", "actor": "accountant_01" },
      { "at": "2026-09-15T11:05:00+03:00", "from": "в реестре", "to": "компенсирован", "actor": "accountant_01" }
    ],
    "rerun_of": null,
    "no_receipt": false
  }
}
```

**Поля:**

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | string | да | Уникальный идентификатор: `gs-<NNN>` |
| `source` | string | да | Откуда: `interview_emp_01`, `synthetic_receipt_01`, `bank_pdf_01` и т.д. |
| `version` | string | да | Дата сбора/генерации в ISO |
| `input.type` | enum | да | `receipt_photo` \| `receipt_pdf` \| `mixed_batch`. `mixed_batch` — одна загрузка, содержащая несколько файлов (например, фото и PDF по одному курсу); запись разворачивается в отдельные расходы, и **каждый расход наследует `receipt_photo` или `receipt_pdf` от своего файла**, поэтому в разбивке SC-02 `mixed_batch` не остаётся отдельной ветвью |
| `input.file_ref` | string | для фото/PDF | Путь к обезличенному оригиналу, вне публичного репозитория |
| `input.ocr_text` | string | для фото | Сырой текст OCR (с ошибками, если они есть) |
| `input.pdf_text` | string | для PDF | Текстовый слой PDF как он извлечён; пустая строка, если слоя нет |
| `input.merchant_raw` | string | да | Наименование продавца как пришло (из чека или из PDF) |
| `input.amount` | number | да | Сумма операции в рублях |
| `input.date` | string | да | ISO 8601 |
| `input.payment_method` | enum | нет | `cash` \| `card` \| `sbp` \| `unknown` |
| `reference.merchant_canonical` | string | да | Каноническое имя продавца (проверка SC-04) |
| `reference.category` | string | да | Целевая категория расхода (из `docs/glossary.md`) |
| `reference.subcategory` | string | нет | Уточнение категории |
| `reference.vat_rate` | string | нет | Ставка НДС, если определена |
| `reference.reimbursable` | bool | да | Эталонный вердикт «компенсируется / нет» по политике (проверка SC-13) |
| `reference.confidence` | number | да | Уверенность эталона 0–1 (1 = бухгалтер уверен на 100%) |
| `reference.notes` | string | нет | Комментарий: почему такая категория и такой вердикт |
| `meta.segment` | string | да | Всегда `employee_expense_reimbursement` |
| `meta.company_id` | string | да | Псевдоним компании: политика компенсации у каждой своя |
| `meta.employee_id` | string | да | Псевдоним сотрудника для группировки |
| `meta.pain_ref` | string | нет | Ссылка на боль из PRD, которую пример иллюстрирует |
| `meta.capture_condition` | enum | нет | `clear` \| `angled` \| `overexposed` \| `low_contrast` \| `partial` — условие съёмки |
| `run.submitted_at` | string | да | ISO 8601: когда расход отправлен сотрудником (нужно для SC-09: split «отправлен / попал в реестр») |
| `run.in_registry_at` | string | да | ISO 8601: когда расход появился в реестре бухгалтера; расхождение с `submitted_at` даёт лаг из SC-09 |
| `run.flagged_at` | string | нет | ISO 8601: когда система пометила расход спорным (числитель SC-11) |
| `run.decided_at` | string | нет | ISO 8601: когда бухгалтер согласовал или отклонил; разница с `flagged_at` — срок из SC-11 |
| `run.status_final` | enum | да | `в реестре` \| `отклонён с причиной` \| `компенсирован` \| `без чека` — проверка SC-03 и SC-19 |
| `run.rejection_reason` | string | если отклонён | Обязательна при `status_final = отклонён с причиной` (SC-03) |
| `run.status_log` | array | да | История смен статуса `[{at, from, to, actor}]` — проверка SC-20; минимум один элемент |
| `run.rerun_of` | string | нет | `id` записи, повторная обработка которой эмулируется; SC-15 сравнивает категорию с этой записью на n ≥ 50 |
| `run.no_receipt` | bool | нет | `true`, если расход заявлен без документа вовсе (PRD, открытый вопрос №5); такие записи не входят в SC-02 |

`run.*` появился специально: критерии SC-09, SC-11, SC-15, SC-19 и SC-20 помечены «Да, скрипт», но без временных меток, финального статуса и признака повторного прогона их нельзя посчитать по golden-записи — скрипт не отличил бы «ещё не обработан» от «обработан, но не попал в реестр».

`meta.company_id` появился специально: без него нельзя проверить SC-14 (категория обязана принадлежать справочнику конкретной компании) и SC-13 (вердикт зависит от политики, а не от общей логики).

## Владелец датасета

| Роль | Ответственность |
|---|---|
| **Quality Engineer** | Владелец: структура, формат, версионирование, приёмка новых примеров, запуск evals |
| **Product / VO** | Источник живых примеров из интервью, валидация категорий и вердиктов с респондентами |
| **AI Engineer** | Генерация синтетических примеров для покрытия edge-кейсов, парсинг OCR и текста PDF |
| **Бухгалтер-респондент** | Подтверждает эталонный вердикт `reimbursable` под политику своей компании |

**Процесс добавления примера:**
1. Новый пример кладётся в `data/golden/inbox/<source>_<date>.jsonl`
2. Quality проверяет формат, дубликаты, обезличивание, соответствие глоссарию категорий
3. Принятый пример мержится в основной файл `data/golden/v<YYYYMMDD>.jsonl`
4. Тег версии в git: `golden-dataset-v<YYYYMMDD>`

## Критерии приёмки примера в датасет

- [ ] Формат валиден по JSON-схеме (см. `schemas/golden-example.json`)
- [ ] `reference.category` существует в `docs/glossary.md`
- [ ] `reference.reimbursable` подтверждён бухгалтером-респондентом под политику его компании
- [ ] `reference.confidence` обоснована (если < 0.9 — есть `notes` почему)
- [ ] `meta.pain_ref` ссылается на существующую боль из PRD
- [ ] Нет PII: ФИО, номера карт, реальные ИНН компаний — обезличены по правилам раздела «Происхождение и версия данных»
- [ ] Есть `source` и `version` для трассируемости
- [ ] Для фото указан `meta.capture_condition`, для PDF — заполнен `input.pdf_text` (в том числе пустой строкой при отсутствии слоя)
