# Черновик DoD команды (Definition of Done)

> DoD — спека для автопроверки: что проверит judge, решаете вы. Каждый критерий проверяем: есть/нет, число, ссылка.

---

## Принципы

1. **Проверяемость** — каждый критерий даёт бинарный результат (pass/fail) или число с порогом
2. **Автоматизируемость** — то, что можно проверить скриптом/оценщиком, должно проверяться автоматически
3. **Согласованность** — DoD согласован со всей командой, изменения — только через PR с обсуждением
4. **Версионирование** — DoD версионируется вместе с кодом, тег `dod-v<YYYYMMDD>`

## Процесс согласования и изменений

1. **Инициализация** — этот черновик обсуждается на планёрке командой, правки вносятся в PR
2. **Утверждение** — после согласия всех ролей PR мёржится, ставится тег `dod-v<YYYYMMDD>`
3. **Изменения** — любое изменение DoD только через PR с ревью от Quality + минимум одной другой роли
4. **Проверка на приёмке** — на демо лабы команда показывает: «Вот наш DoD, вот чек-лист, вот что зелёное, вот что нет»

## Чек-лист для автопроверки в CI (планируемый)

```yaml
# .github/workflows/dod-check.yml (планируется к Lab 2)
name: DoD Check
on: [pull_request]
jobs:
  dod-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Check repo structure
        run: python scripts/check_repo_structure.py
      - name: Validate .env.example
        run: python scripts/check_env_example.py
      - name: Validate golden dataset schema
        run: python -m jsonschema data/golden/*.jsonl schemas/golden-example.json
      - name: Check success criteria format
        run: python scripts/check_success_criteria.py docs/quality/success-criteria.md
      - name: Word count brief.md
        run: |
          wc=$(wc -w < docs/brief.md)
          if [ $wc -gt 500 ]; then exit 1; fi
      - name: Glossary term count
        run: |
          cnt=$(grep -c '^## ' docs/glossary.md)
          if [ $cnt -lt 15 ]; then exit 1; fi
```

## Открытые вопросы (к согласованию на планёрке)

1. **Порог автотестов** — требуем ли 100% coverage по AC с первой US или вводим постепенно?
2. **Глоссарий** — 15 терминов минимум или больше? Кто валидирует определения (Product или вся команда)?
3. **Golden dataset** — валидируем ли схему на CI с Lab 1 или ждём Lab 2?
4. **ADR** — обязателен ли ADR на каждое архитектурное решение или только на ключевые (модель, подход, хранение)?
5. **Deploy URL** — считаем ли hello-world «продом» или нужен отдельный staging?
