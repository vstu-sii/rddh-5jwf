# Деплой

Прод существует с первой недели и дальше только наращивается. Сейчас в проде — заглушка (`GET /` и `GET /health`), задеплоенная как есть из `Dockerfile`.

## Хостинг: Render.com

Выбран за бесплатный тир, деплой прямо из GitHub-репозитория по Blueprint (`render.yaml`) и нативную поддержку Docker — не нужно ничего дополнительно настраивать под конкретную платформу.

## Как задеплоить (один раз, вручную)

1. Зарегистрироваться / зайти на [render.com](https://render.com) через GitHub-аккаунт.
2. **New** → **Blueprint** → выбрать репозиторий `vstu-sii/rddh-5jwf`.
3. Render считает `render.yaml` из корня репо и предложит создать веб-сервис `rddh-hello-world` (Docker, free plan).
4. Подтвердить создание — Render соберёт образ по `Dockerfile` и задеплоит.
5. После первого успешного деплоя Render выдаст публичный URL вида `https://rddh-hello-world.onrender.com`.
6. Проверить: `GET /health` должен вернуть `{"status": "ok"}`.
7. Вписать URL в [README.md](../README.md) (раздел «Прод») и в это поле:

   **Прод-URL:** `TODO — вписать после первого деплоя`

## Дальнейшие деплои

Render передеплоивает сервис автоматически при пуше в `main` (Auto-Deploy включён по умолчанию для Blueprint-сервисов). Ручные шаги выше нужны только один раз, для первого подключения репозитория.

## Переменные окружения в проде

Значения по умолчанию заданы в `render.yaml`. Реальные секреты (например, боевой `LLM_API_KEY`) добавляются вручную в Render Dashboard → Service → Environment — не в git.

## Откат

Render Dashboard → Service → Events → выбрать предыдущий успешный деплой → **Rollback**.
