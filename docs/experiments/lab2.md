## 2. Spike №1 — PDF text layer → render + OCR

**Вопрос:** работает ли fallback для PDF без текстового слоя на простом чеке?  
**Эксперимент:** сгенерированы текстовый PDF, сканированный PDF, чистое и слегка размытое/наклонённое фото. Извлечение — PyMuPDF; OCR — Tesseract `rus+eng`.

| Вход | Маршрут | Наблюдение |
|---|---|---|
| Текстовый PDF | `pdf_text` | Текст извлечён, сумма найдена |
| Сканированный PDF | `render+ocr` | Текстовый слой пуст; fallback отработал, сумма найдена |
| Чистое фото | OCR | Дата, сумма и ИНН найдены |
| Слегка ухудшенное фото | OCR | Дата, сумма и ИНН найдены, но часть букв распознана неверно |

**Результат: сработало иначе.** Технический fallback сработал на синтетических файлах. При этом OCR вернул правдоподобный текст с символьными ошибками (например, `RUB` распознано как похожие кириллические символы; `ООО` на ухудшенном изображении — как `000`). Значит, «текст получен» не равно «поля верны». Не проверялись настоящие термочеки, блики, обрезка, длинные PDF, таблицы и QR.

## 3. Spike №2 — защитный post-LLM gate

**Вопрос:** может ли независимое от LLM правило отменить очевидно опасный ответ?  
**Эксперимент:** небольшой временный Python-прототип получил четыре ответа, включая уверенную категорию без чека, смешанную корзину и категорию вне allowlist.

| Сценарий | Результат gate |
|---|---|
| Нет чека, модель уверенно выбрала «Покупки» | Перевёл в `Не определено` + `needs_review=true` |
| Смешанная корзина, модель уверенно выбрала категорию | Перевёл в `Не определено` + `needs_review=true` |
| Категория отсутствует в allowlist | Отклонил ответ, `needs_review=true` |
| Обычная допустимая категория | Пропустил без изменений |

**Результат: сработало.** Минимальный gate способен технически переопределить модель в трёх заданных случаях. Это проверка реализуемости идеи, а не доказательство полноты бизнес-правил: классификатор смешанных корзин, policy engine, tenant isolation и интеграция с API не тестировались.

## 4. Что не проверено и решение

- Qwen повторно не запускалась: локальные endpoints LM Studio/Ollama в среде эксперимента недоступны. Новых выводов о качестве модели нет; Lab 1 остаётся единственным измерением.
- **Не строить auto-approval на OCR confidence или факте непустого OCR-текста.** Критичные поля должны иметь независимые проверки формата/согласованности; сомнение — `review`.
- Сохранить архитектурное разделение: LLM предлагает категорию, детерминированные правила имеют приоритет.
- До production провести следующий spike на размеченной выборке реальных по структуре, но обезличенных фото/PDF: отдельно exact match суммы/даты/продавца, QR↔OCR conflicts, доля ручной проверки и p95 на целевом железе.
- Эти два спайка **не подтверждают production-readiness** и не закрывают критерии golden dataset из `docs/quality/golden-dataset-plan.md`.
