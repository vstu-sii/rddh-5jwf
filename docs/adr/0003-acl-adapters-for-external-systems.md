# ADR-0003: Внешние системы — только через ACL-адаптеры, без общего API Gateway

- **Статус:** предложено (Delivery), на приёмке у Product
- **Дата:** 2026-10-15
- **Затрагивает:** `llm_adapter`, `fns_adapter`, `llm_runtime`, внешние «Облачный LLM-провайдер» и «ФНС „Проверка чека“» — [C4 Container](../architecture/c4-container.puml), [aact.config.ts](../../aact.config.ts)

## Контекст

У системы две внешние зависимости с чужой моделью данных и чужими отказами:

1. **LLM.** Решение в `docs/model-candidates.md`: старт на локальной Qwen2.5-7B (Ollama), резерв — GPT-5 mini или GigaChat 2 Lite, при исчерпании бюджета — правила «продавец → категория». Там же требование: «завернуть инференс за единый интерфейс `categorize()`, чтобы провайдеры были взаимозаменяемы».
2. **ФНС «Проверка чека».** Доступ к API выдаётся по заявлению с электронной подписью; формат ответа и лимиты задаёт ФНС.

## Решение

- Каждая внешняя система — за своим адаптером с тегом `acl`: `llm_adapter` и `fns_adapter`. Конвейер распознавания знает только их внутренний контракт (`categorize(merchant, items, policy)`, «реквизиты по QR»), а не форматы провайдеров.
- `llm_adapter` владеет выбором провайдера, лимитами токенов (`max_input_tokens=1000`, `max_output_tokens=150`), учётом бюджета (80/90/100%) и деградацией на правила. Локальная модель `llm_runtime` — внутренний контейнер за тем же адаптером.
- В интернет выходят только адаптеры: в compose они единственные подключены к сети `egress`, сеть `backend` — `internal`.
- **Правило aact `apiGateway` отключено.** Оно требует, чтобы ACL ходил во внешние системы через общий API Gateway. В MVP два адаптера с разными протоколами и лимитами; общий шлюз дал бы ещё один компонент без выигрыша. Остальные 7 правил aact включены.

## Альтернативы

| Вариант | Почему не берём |
| --- | --- |
| Вызывать LLM/ФНС прямо из `recognition_worker` | Формат провайдера и логика бюджета протекают в конвейер; смена модели = правка конвейера. Нарушает aact `acl`. |
| Общий egress API Gateway (Kong, Envoy) | Оправдан при многих внешних интеграциях; для двух — лишний компонент, конфигурация и точка отказа. |
| Только облачная LLM, без локальной | Противоречит итоговому решению в `model-candidates.md` (старт с Qwen без бюджета на API). |

## Цена решения

- **Ретраи, таймауты и circuit breaker пишутся в каждом адаптере отдельно** — при двух адаптерах это дублирование, при пятом станет долгом. Порог пересмотра: третья внешняя интеграция → новый ADR про egress-шлюз и включение `apiGateway`.
- **Нет единой точки наблюдаемости исходящего трафика** — метрики вызовов (латентность, ошибки, токены) логирует каждый адаптер сам, в общем формате из `docs/quality/success-criteria.md` (E-01…E-03).
- **Локальная модель — тяжёлый контейнер** (~5 ГБ весов): в dev он поднимается только с профилем `local-llm`, по умолчанию адаптер работает как заглушка. Качество локального варианта проверяется отдельно на golden dataset.
- **До получения доступа к API ФНС** `fns_adapter` возвращает «реквизиты недоступны», и конвейер идёт по ветке OCR/текста PDF.
